# Plan: Home Blog block

Replace the last temporary dump with the three latest posts, each with its translated topic before the date: a featured card plus two on desktop, a carousel on mobile. The home page ends here: there is no footer. This replaces the earlier draft, which predates the topic badge from the design of 2026-11-01.

Related: [[2026-10-29-home-page-design]], [[Home Page Handoff]], [[Blog Page Handoff]], [[Data Model]]. Previous: [[2026-10-30-home-skills]]. Next: [[2026-10-30-home-motion]].

## Decisions

- **Topics are tables (owner's decision).** `post_topics` and `post_topic_translations`, shaped like `skill_domains`. The Blog handoff's enum with labels in `messages` is not used, and neither are the topic labels in the design's `Home.blog.topics` and `Blog.topics`: labels are read from the database, only the filter's "All" stays a message, per [[ADR-0003 Content Localization]], and the admin can add a topic without a deploy.
- **One post, one topic, always (owner's decision).** `posts.topic_id` is `NOT NULL`, `on delete restrict`, for drafts too: the form asks for it at once. A many-to-many link has no use: the design has one badge and a single-select filter.
- **Topic counts come from a join (owner's requirement for the Blog page).** The filter shows how many posts a topic has, including 0: `post_topics` left joined with published `posts`, grouped by topic. Nothing stores a counter, because a stored number can drift from the rows. The query itself is written with the Blog page; Task 1 runs it once as a check. `posts_topic_id_idx` serves that join.
- **All eight locales are filled now (owner's decision).** The wording below is approved. A missing label would still fall back to English, field by field, like every other translation.
- **`getLatestPosts` returns the label, not the key** (Claude's call). The home page shows the text only. The Blog page needs `key` for `?topic=technical` and gets it in its own query.
- **A `postTopics` cache tag** (Claude's call). `getLatestPosts` embeds topic labels, so it carries the tags of both entities, like `getExperience` does with skills. Editing a topic in the admin refreshes `postTopics` and nothing else.
- **The badge lives in `PostCard`** (Claude's call). It moves to `shared/ui` when the Blog page becomes its second user.
- **No block without posts** (Claude's call), the same rule as "My top skills".
- **Reuse the Carousel** from [[2026-10-30-home-experience]], with the same one-DOM rule.
- **Links:** post cards go to `/blog/<slug>`, "All posts" to `/blog`. Both lead to the 404 page until the Blog page exists.
- **Time zone:** `timeZone: "UTC"` in the i18n request config. Without it next-intl uses the machine's zone, so a local build and a Vercel build could print different dates for the same post.
- **The title is not a link on the home page** (Claude's call), as in the prototype: only "Read more" leads to the post, like "Learn more" on the Experience cards. The Blog page links its titles in its own card.
- **Excerpt** renders as plain text through `toPlainText`: the card is 2–3 sentences with no formatting.

## Review focus

- A long label in a narrow card ("Oprogramowanie" at 1024 px): the date moves to its own line whole, nothing overflows (Task 4).
- A translated label next to English content on `/ru`: the badge is Russian whatever the post's language is (Task 4).
- A date near midnight UTC prints the same day in any machine zone (Task 3).
- `Hobby` has no posts and must still count as 0 (Task 1).
- `brand` text on a 14% `brand` tint at 11 px: the handoff measured `brand` on `card` only (Task 4).
